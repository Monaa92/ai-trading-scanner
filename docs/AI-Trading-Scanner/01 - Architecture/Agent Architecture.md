# Multi-agent architecture

Extension baseline: 2026-09-14. A trading agent is an independently configured participant, not an LLM instance. Phase 4 implements pure agent-attributed strategy decisions and immutable proposal intent. Phase 5 adds accepted allocation ownership, risk decisions and reservations without execution. The Phase 6 foundation adds agent-attributed simulation/order/fill/portfolio records but no runner. One deterministic participant may use no AI; one future AI service may evaluate several isolated participants. See [[01 - Architecture/Execution/Execution Modes]], [[01 - Architecture/Portfolio Accounting/Capital Allocation]] and [[03 - Experiments/Autonomous Experiments]].

## Identity and isolation

An Agent has stable agent_id and owner_id, lifecycle, and immutable configuration revisions binding strategy/version/parameters, model/AI configuration, risk profile, trade-management policy, data/run mode, execution environment, submission mode, approval policy, operating context, account/allocation and optional experiment participant ID. Decisions, approvals, orders, fills, positions, trades, equity history and statistics carry agent_id plus run/participant and allocation IDs. A reused display name is not an identity. Configuration changes create performance segments without overwriting history.

Agents never call broker/exchange or market-data provider APIs. The Phase 4 `StrategyEvaluationContext` contains one agent identity, one strategy/configuration identity, a canonical causal market-data slice, a common six-series indicator snapshot, a separately versioned cost estimate and authority context. Pure evaluators return `TRADE_PROPOSAL` or first-class `NO_TRADE`. The application execution coordinator alone will invoke [[01 - Architecture/Broker Architecture]] in a later phase. Strategy profile and AI model are independent experiment dimensions; Phase 4 configurations contain no model field.

The application orchestrator supplies an authenticated agent context; a request payload cannot choose another agent's authority. Agent-scoped repositories enforce context on reads and writes, and relational ownership checks reject cross-agent foreign keys. Domain snapshots expose only the agent's allocated ledger and a pass/block/headroom view of parent-account constraints, not another agent's private balances/orders. An authorized owner/research reporting service can compare agents; trading participants cannot read each other's state. A shared infrastructure failure may affect all agents, but its cause/scope must be explicit.

Shared immutable data includes normalized bars, calendars and pure feature artifacts keyed by full input/version hashes. Mutable indicator state is isolated or computed as a pure function; a cache key cannot omit parameters or data vintage. Fan-out delivers the same available-at batch/cutoff to each experimental participant. Record per-agent delivery/processing times and missing messages. One slow AI call cannot block the shared stream or another agent's decision clock. Separate queues, bounded resources and event-indexed random streams prevent scheduler and RNG contamination. Infrastructure contention is measured as an experiment limitation, never disguised as strategy quality.

## Concurrency and execution ownership

Use one fenced writer per real/simulated funding account, not one global writer for all agents. Independent accounts proceed independently. Within a shared account the coordinator atomically validates both agent allocation and parent-account reservations/constraints. A deterministic queue rule and fairness policy are registered when account contention is studied; a first-arrival race must not masquerade as an independent comparison. Lock scope is AGENT, ACCOUNT, EXPERIMENT or SYSTEM with reason and issuer. Effective permission is the intersection of all applicable permissions; any applicable lock blocks new exposure.

Default four-agent experiment: independent simulated accounts/ledgers or separate verified broker-paper accounts, each with its own EUR50 starting allocation. No capital borrowing, shared position slot or netting between arms. EUR200 is the sum of four simulated starting ledgers, not a live allocation request. Shared market data does not mean shared cash.

Several agents sharing one broker account is an eventual supported architectural shape, **not initially certified execution**. A broker may report one net symbol position. Ownership must be attributable from intent→order→fill→agent before internal lots/fees/protection can be split. V1 shared-account execution blocks conflicting same-symbol ownership; unknown/manual fills lock the parent account. Do not infer attribution from a net position or use Agent A's stop to sell Agent B's shares. OCO/protection, cancellation races, settled-cash allocation and aggregate exposure need adapter-specific tests before enabling that shape. Prefer dedicated accounts for independent experiments; a coupled-account study must be labeled accordingly.

## Domain additions and dependency direction

Agent registry/configuration resolves a context; strategy and AI consume frozen context; risk receives own ledger plus parent constraints; [[01 - Architecture/Execution/Safety Gate]] checks authority/health/modes; [[01 - Architecture/Execution/Approval Workflow]] governs human consent; account coordinator commits intent/reservation/outbox. [[01 - Architecture/Execution/Trade Management]] proposes versioned amendments through the same boundaries. No domain service imports an agent worker, UI or LLM implementation. Account reconciliation remains centralized per account and projects attributed facts into each agent ledger.

No participant may activate itself, switch environment/mode, raise limits, allocate funds, change frozen configuration, clear its own lock or mutate another participant. Administrative commands require owner-scoped authority and an audit event. Emergency restriction can come from trusted risk/safety supervisors and never grants additional exposure. [[01 - Architecture/Data Model]] extends existing records rather than duplicating a complete database per agent.
