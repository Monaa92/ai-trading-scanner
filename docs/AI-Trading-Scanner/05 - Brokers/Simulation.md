# Simulation broker

Status: **PARTIAL — PHASE 6 CONTRACT FOUNDATION ONLY**. Immutable offline execution-model, order, fill and market-event contracts are implemented in `ai_trading_scanner.simulation`; no adapter, scheduler or order-processing service exists.

`SimulationBrokerAdapter` will implement every method in [[01 - Architecture/Broker Architecture]] without network access or credentials. It will consume immutable order intents and causal market events, enforce an explicit capability snapshot, model cancellations/rejections/ambiguity, apply the frozen transaction-cost/execution profile and emit deterministic events under a fixed run manifest. The foundation exposes no broker-shaped authority or network port.

The V1 foundation supports only market-order contracts, Decimal quantities on a configured increment, no partial fills and no randomness. Eligibility must be strictly later than submission. A fill uses the next eligible execution-bar open and is recorded only when that future bar becomes causally available. No eligible bar before expiry means no fill; a gap uses the next eligible open. Commission, spread, slippage and other fees remain separate auditable monetary components and are not double-counted in fill price. These assumptions are content-identified and versioned under [[00 - Project/Decisions/ADR-033 - Deterministic Phase 6 replay foundation]].

The later state projection will use `PENDING → ELIGIBLE → FILLED` or one terminal `REJECTED`, `CANCELLED` or `EXPIRED` outcome. Transitions are immutable events; duplicate commands/events are idempotent and a terminal state cannot reopen. A known closed/halted session, zero/unavailable modeled liquidity, unsupported quantity/order capability, stale source or missing eligible interval cannot fabricate a fill. Cancellation becomes effective only at its causal modeled acknowledgement, so a fill that precedes acknowledgement remains valid. These lifecycle behaviors are design requirements and are not implemented by the current immutable order/fill objects.

Each `(run_id, agent_id, allocation_id)` owns independent cash, reservations, positions, realized/unrealized P&L, costs, risk state and order attribution. Equivalent shared market snapshots are read-only inputs. Simulation must reject unsupported order features, stale required data and cross-agent access. NO_TRADE produces a decision event only.

Phase 6 completion requires executable lifecycle behavior, causal strategy/risk orchestration, reservation consumption/release, stop/target handling, restart/idempotency tests and reconciliation with the authoritative ledger. Contract existence alone is insufficient. PAPER, LIVE, IBKR and Kraken remain unavailable.
